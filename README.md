# Aegis VIP Threat Monitoring Platform

Aegis collects, analyzes, and triages online threats, impersonation, leaks, and
coordinated campaigns against monitored VIPs. It is a Python modular monolith:
one codebase, one image per role, deployed with Docker Compose.

- **Pipeline:** collectors publish raw items; a normalizer deduplicates them; an
  analysis worker runs mention resolution, text, impersonation, and leak
  detection; a media worker handles hashing, embeddings, OCR, and video; an
  in-process scorer turns detections into scored incidents.
- **Storage:** PostgreSQL 16 with pgvector and pg_trgm (system of record, full-text
  search, vector search), RabbitMQ for work queues, MinIO for media and
  object-locked evidence.
- **Presentation:** a FastAPI REST + WebSocket API, an alerting service
  (email and Slack), and a React dashboard.

The design, requirements, and implementation plan live in `docs/`.

## Prerequisites

- Python 3.12 and [uv](https://docs.astral.sh/uv/)
- Node.js 22 and npm 10+ for the dashboard
- Docker with Docker Compose v2
- GNU Make (optional; every target is a short command)

## Quick start

```bash
cp .env.example .env      # change every "change-me" value before real use
uv sync                   # install core and dev dependencies
make up                   # build and start Postgres, RabbitMQ, MinIO, api, worker, frontend
make migrate              # apply database migrations
```

The API is then at http://localhost:8000 (health at `/health`), the dashboard at
http://localhost:5173, the RabbitMQ management UI at http://localhost:15672, and
the MinIO console at http://localhost:9001.

For dashboard development, run the Vite dev server against a running API:

```bash
cd frontend
cp .env.example .env      # VITE_API_URL, defaults to http://localhost:8000
npm install
npm run dev               # http://localhost:5173
```

## Common commands

| Command | Purpose |
|---|---|
| `make test` | Run the pytest suite |
| `make lint` | ruff check, ruff format check, and mypy |
| `make format` | Format with ruff |
| `make up` / `make down` | Start / stop local services |
| `make logs` | Tail service logs |
| `make migrate` | Apply Alembic migrations |
| `make revision m="message"` | Create an autogenerated migration |
| `make data` | Clone or update the private `Aegis-data` checkout (`data/private/`) |
| `make eval` | Evaluate detectors on the private golden set (`data/private/golden/`) |
| `make eval-smoke` | Evaluate detectors on the public smoke set (`data/smoke/`) |
| `make eval-gate` | Fail if precision or recall regressed vs the baseline |
| `make fetch-models` | Pre-download ML model weights into `./models` |
| `make frontend-install` | Install dashboard dependencies (`npm ci`) |
| `make frontend-dev` | Run the Vite dev server |
| `make frontend-test` | Run the Vitest suite |
| `make frontend-build` | Type-check and build the dashboard |
| `make e2e` | Seed and run the Playwright suite against a running API |

Heavy dependencies are optional groups, not part of the base install. Add them
only when working on the matching area:

```bash
uv sync --group analysis   # toxicity model runtime (torch, transformers)
uv sync --group media      # OpenCLIP, PaddleOCR, sentence embeddings
uv sync --group capture    # Playwright
uv sync --group collectors # Telethon
```

```
  collectors/   replay, manual URL submission, Telegram, GitHub

  eval/         golden-set runner and CI gate (python -m aegis.eval)

deploy/         Grafana dashboards and Prometheus rules
data/smoke/     public synthetic smoke set (27 items)
data/private/   private Aegis-data checkout: golden set, caches, reports
docs/           design, requirements, tasks, data-protection
```

## Testing and evaluation

```bash
make test           # unit and smoke tests (pytest)
make eval           # per-detector, per-language report from the golden set
make eval-gate      # regression gate used by CI
make frontend-test  # Vitest component tests
make e2e            # Playwright: login -> live incident -> assign -> note -> resolve
```

The golden set is labelled per detector and language. Until the real detectors
land, `aegis.eval` evaluates a reference keyword detector so the harness, the
report format, and the gate are exercised end to end.

## Docker images

One `Dockerfile` builds four Python role targets, selected per Compose service,
plus the dashboard image built from `frontend/Dockerfile`:

| Target | Contents | Runs |
|---|---|---|
| `api` | core only | `aegis-api` |
| `analysis` | core + collectors + analysis runtime | `aegis-worker`, `aegis-normalizer` |
| `media` | core + vision stack + ffmpeg | `aegis-media-worker` |
| `capture` | core + Playwright/Chromium | `aegis-capture` |
| `frontend` | Node build + nginx static `dist/` | dashboard SPA |

## CI/CD

- `.github/workflows/ci.yml` — ruff, mypy, pytest, pip-audit, Compose validation,
  frontend typecheck/Vitest/build/npm-audit, and the Playwright end-to-end suite.
- `.github/workflows/cd.yml` — after CI passes (or on a `v*` tag), builds the four
  Python targets plus `frontend` and pushes `ghcr.io/<owner>/aegis-<target>`.

## Collector policy

Aegis only uses documented, terms-compliant access methods. Sources that prohibit
automated collection are reached through manual URL submission instead. See the
source access matrix in `docs/design.md` and the per-source review in
`docs/data-protection.md` (task 19.3).

## Legacy

The pre-reset Twitter-centric codebase is preserved on the `legacy/v0` branch
and the `legacy-v0` tag. It is not imported anywhere on `master`.
